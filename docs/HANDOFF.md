## Goal
Scheduled/user-briefed AI Shorts → local render (Kokoro TTS, Python/FFmpeg) → review → upload to
YouTube/Instagram across channels. The AI (Codex *or* Claude) is only the "brain": it returns a
strict JSON script + scene plan; all pixels, audio and encoding are local and cost no tokens.

## Working rules for the relay
1. Start: `git status`, `git log -5 --oneline`, read this file. One agent on the branch at a time.
   **Never commit on `main`:** work on `dev` (worktree `../tubeforge-dev`) or a new feature branch/worktree, then post a review (changes + validation evidence). Agents may merge to `main` only after asking and getting the operator's explicit approval for that specific merge; ask every time, and never push or force-push a remote without being asked. Remove temporary branches/worktrees once merged.
2. Commit at every green checkpoint; before stopping (or near your token limit) commit and edit
   **Next step** below with a concrete file/command. Commit messages carry no AI attribution trailers.
3. Judge video work by looking at frames: `ffmpeg -i x.mp4 -vf "fps=1/3,scale=270:480,tile=6x2" -frames:v 1 sheet.png`, then view the PNG.
4. Python with renderer deps: `.venv-benchmark/bin/python` (`PYTHONPATH=src`). Heavy renders: run in background.
5. Do not publish anything. Do not reset script-attempt allowances.
6. `pre-commit` (gitleaks + large-file/generated-file guards) runs on every commit; never bypass it with `--no-verify`.

## Architecture in one screen
- Dashboard (`api/app.py`, port 62065) → durable job → worker (`workers/`, Docker) → `pipeline/orchestrator.py` state machine.
- **Script owner** is per job (`ContentRequest.script_owner`, `codex` default | `claude`), chosen in the Creator Studio form.
  - Codex: root-owned host runner behind `/run/tubeforge-codex/codex.sock` (needs sudo to redeploy; `docs/deploy/codex-runner-runtime.md`).
  - Claude: user-level runner `scripts/run_claude_runner.sh` → `data/run/claude/claude.sock`
    (`src/tubeforge/host_claude_runner.py`; CLI binary resolved from the VS Code extension or `TUBEFORGE_CLAUDE_BIN`).
    Start it before using Claude jobs (`systemctl --user` unit in `docs/deploy/tubeforge-claude-runner.service`).
  - Routing: `providers/content/factory.py::ScriptOwnerRouter`. Config: `pipeline.claude` in `config/production.yaml`.
- **Reference Shorts path** (`m6-content-v8`, 9:16, 30–90 s, default 60): package carries `reference_short` scenes.
  Orchestrator branches to `pipeline/reference_short.py` → `rendering/shorts/` (layout, timeline, audio, encode, motion, icons, logos, mascot).
  Legacy v1–v7 / 16:9 box-and-caption jobs are refused.
- Preview = 720×1280 draft; final = 1080×1920. Both pass the library's QA (decode, loudness −15..−13 LUFS, TP ≤ −1.5).
- Publishing page: title/description suggestion (`pipeline/publication_suggest.py`), thumbnails (`pipeline/thumbnail.py`). Instagram publisher NOT STARTED.

## Gotchas learned
- **Batch jobs are strictly FIFO (6 Nov):** a batch job starts only when every earlier batch job is finished (`final_ready`, failed or cancelled). A script parked at `script_approval_required` blocks all later batch jobs, including the 22:00 overnight production; a script rejection does not unblock it, deleting the job does. Clear stray trial jobs before the overnight window.
- Dashboard first load asks for a thumbnail/ffprobe per ready job; on a busy host `/api/jobs` took 12 to 64 s and the worker once crashed with `database is locked` (it restarted itself). Check host load before judging dashboard slowness.
- **Source-card capture fixes (6 Nov, found on a real render of the Claude Code email Short):** `pipeline/capture.py` now hides fixed/sticky overlays that do not contain the quote (a dev.to promo banner was printed over the quote), lets long tokens wrap, and scales the reported document size to visual pixels (Hacker News cards were cut off on the right because the zoomed table page reports 360 px for a 540 px layout). `CAPTURE_POLICY` is now `source-capture-v6-dark-reader-overlays`, so Codex's `scripts/benchmark_story_short.py` will call its stored v5 proof stale. Verified on the real HN, dev.to and AWS pages in the worker, and by three new real-Chromium tests (`TUBEFORGE_CAPTURE_BROWSER=1`; needs `pip install playwright` in the venv) that fail on the old code. Cheap path to submit a Short with small sources: `POST /api/videos` with `sources[].excerpt` set (no fetch, no research).
- **Brief sources must be small HTML pages on an allowlisted host (6 Nov):** the fetcher accepts only HTTPS `text/html` or `text/plain` (so GitHub API JSON is rejected) and, if fewer than two sources are usable, silently falls back to a Claude web-research step that picks its own sources, which can differ from the brief's. The assembled prompt counts excerpts more than once: three large pages (GitHub issue with 84 comments, a dev.to post, a 420-comment HN thread) overflow the 90,000-character limit; two pages of about 9,000 characters each work. For a thread, link the single comment's own page (HN `item?id=<comment id>`) instead of the thread.
- **Claude Code email-in-User-Agent video (6 Nov, PRODUCED, not approved or published):** job `3b207d32…` sits at `publication_approval_required`; final 1080x1920, 58.3 s, -14.3 LUFS / -2.4 dBTP, `qa_check.py` no FAIL (WARN: dead stretches in scenes 1, 10, 11; music under speech; no thumbnail yet); review copy `artifacts/review/claude-code-email-20261106/final.mp4`. - A brief whose sources are very long (e.g. an IETF draft plus two Stripe pages) fails before any model call: assembled prompt over the 90,000-character limit. Drop or shorten a source.
