TubeForge design guide

The parts every dashboard page is built from. Copy a recipe exactly, change only the words and the IDs, and run the checker. If a page needs something that isn't here, add it here first.

Rules and step-by-step instructions: design/DESIGN.md. Check: python scripts/check_design.py.

Colors

Dark navy surfaces, one accent, four status colors. The accent marks what you can act on right now: primary buttons, focus, the current page, the current stage. Links and headings never use it.

Type

IBM Plex Sans for everything. IBM Plex Mono (tf-mono) only for values a machine produced: job IDs, file paths, durations, commands. Six sizes, three weights (400, 500, 600). Sentence case everywhere, no all-caps labels.

Space and shape

Spacing uses Tailwind's 4 px steps; prefer 1, 2, 3, 4, 5, 6, 8, 10, 16. Three corner radii, each tied to a size of thing. One main column width for every page, left aligned.

rounded-sm 4 px
Badges, checkboxes

rounded-md 8 px
Buttons, fields, notices

rounded-lg 12 px
Panels, lists, dialogs

  • max-w-content (1200 px): the main column on every page.
  • max-w-form (720 px): forms and paragraphs.
  • Gaps between page sections: gap-10. Inside a panel: gap-4 or gap-5.

Panel

Use for: a self-contained tool (a form, a list, a review area). Don't box single fields, single sentences or another panel. Panels are never nested. A page should have few panels; separate the rest with headings and space.

Buttons

Primary: the one action the area is for (at most one per panel or dialog). Secondary: other actions. Quiet: low-stakes actions in dense rows. Danger: deletes or irreversible actions, only inside a confirmation dialog or after a clear label. Labels are verbs that say exactly what happens.

Small size (inside list rows and the top bar): replace h-9 px-4 text-base with h-8 px-3 text-sm.

Approve is unavailable: this video has no audio licence record. Re-render it to fix this.

A disabled button always has a visible reason next to it, linked with aria-describedby.

Links

Use for: going somewhere. Use a button for doing something. Links are body-colored with an underline; they turn the accent color only on hover. Never colored green.

See the prompt size limits in Settings before importing long sources.

Form fields

Every field: a visible label tied with for/id, a unique id, help text when the format isn't obvious. Errors say what's wrong and how to fix it, and set aria-invalid. Stack fields in one column inside max-w-form.

One point per line. The writer keeps your facts and finds sources for them.

Use lowercase letters, numbers and dashes, like week-46.

The writer only plans visuals; your wording is kept word for word.

Dialog

Use for: confirming deletes and irreversible actions, and focused tasks (activity log, video player). Uses the native <dialog>; a form method="dialog" closes it without any JavaScript. Never use alert() or confirm(). Name the exact object and the consequence.

Stage track

The signature element. Shows where one video is in its life: Script, Voice, Render, Review, Publish. Use it on every job row and at the top of a job's detail view. Five step states: done, working, needs you, failed, waiting. Under a step, show elapsed time or a short reason in tf-mono when it's known.

Status badge

Use: one per item, top right of a row, for the item's overall state in plain words. Never show raw state names like failed_validation; use the label table in DESIGN.md.

Notice

Use for: a failure, warning or important fact about one item or page. First line: what happened, in plain words. Second: what to do. Raw error text goes in "Technical details", never in the first line. Add role="alert" only when it appears after the page has loaded.
